# M6.2 Implementation Report

Status: Certification candidate.

## Scope

M6.2 remediation resolves the EWP-01 critical finding that checkout consumption and order cancellation restoration changed inventory without ledger records.

No reservation lifecycle, checkout redesign, order redesign, Prisma schema change, or Catalog Read Model change is included.

## Architecture compliance

- Catalog Read Model remains the current state projection.
- Order Snapshot remains the historical source of truth.
- Product.primaryCategoryId remains the primary category authority.
- Inventory Ledger is now the stock movement history for manual adjustment, checkout consumption, and cancellation restoration.
- AppError remains the standard error contract.

## Inventory Movement boundary

`InventoryMovementService` owns committed stock movement. Callers provide an existing Prisma transaction, and the service updates `Inventory.onHandQuantity` and creates `InventoryLedger` inside that transaction.

Supported movements:

- Manual adjustment.
- Checkout consumption.
- Order cancellation restoration.

## Cart policy

Cart remains non-reserving. Cart validation checks current availability, but cart writes do not mutate inventory quantities and do not create ledger rows.

## Remaining technical debt

- `reservedQuantity` has no active lifecycle in this remediation and should remain inert until a future reservation milestone.
- Error code strings are still distributed across modules; TECHDEBT-001 tracks centralized registry work.
- Order snapshot fallback for legacy records remains as compatibility behavior.
