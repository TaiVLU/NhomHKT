# M6 Local Demo Runbook

This guide captures the local demonstration path verified during M6.3 Release Candidate QA and prepared for M6.4 closure.

## Required Software

- Node.js 20.9 or newer.
- npm 10 or newer.
- SQL Server reachable by `DATABASE_URL`.
- A local database target recognized by the seed safety guard.

## Environment

API environment can be copied from `apps/api/.env.example`.

Required local API values:

```dotenv
NODE_ENV=development
API_HOST=127.0.0.1
API_PORT=4000
WEB_ORIGIN=http://127.0.0.1:3000
DATABASE_URL="sqlserver://127.0.0.1:1433;database=RoSachDb;user=YOUR_USER;password=YOUR_PASSWORD;encrypt=true;trustServerCertificate=true"
JWT_SECRET=replace-with-at-least-32-random-bytes
OTP_PEPPER=replace-with-at-least-32-random-bytes
MAIL_MODE=fake
```

Web environment can be copied from `apps/web/.env.example`.

Required local web values:

```dotenv
NEXT_PUBLIC_API_URL=http://127.0.0.1:4000/api/v1
NEXT_PUBLIC_SITE_URL=http://127.0.0.1.nip.io:3000
```

RoSach is local-only during M6. Do not configure a public domain for demo readiness unless a later deployment milestone approves one.

## Database Preparation

Run migrations, clean only recognized local residue, then seed and validate demo data:

```bash
npx --workspace @rosach/api prisma migrate status
npm run seed:cleanup-local -w @rosach/api -- --confirm-local-cleanup
npm run seed -w @rosach/api
npm run seed:validate -w @rosach/api
```

The seed process creates the canonical 24-book Vietnamese catalog, eight public categories, eight authors, four publishers, four ordered owned images per book, customer, staff, cart, order, snapshot, and inventory ledger data. Re-running the seed reconciles the deterministic M6 baseline with non-seed checkout/admin ledger deltas, so real runtime stock movements remain effective and stock reconstruction stays deterministic. Cleanup deactivates only bounded QA/legacy residue and never deletes order/cart/inventory history.

1. Open `/admin/login`.
2. Log in with `M3_DEMO_STAFF_EMAIL`.
3. Inspect `/admin/catalog`.
4. Inspect `/admin/orders` (`/admin/don-hang` remains a compatibility route).
5. Open an order detail page from the order list.

The M7.4E Admin Operations smoke route matrix is:

- `/admin/dashboard`;
- `/admin/revenue`;
- `/admin/product-statistics`;
- `/admin/orders`;
- `/admin/catalog`;
- `/admin/inventory`.

Admin and Staff can read all six pages. Staff must display `Nhân viên · chỉ đọc` and must not receive create, delete, stock-adjustment or cost-price controls. Only `/admin/login` is available to anonymous users; anonymous or Customer access to operational Admin routes is denied without rendering the Admin shell and redirected to `/`. Customers receive the safe denial message `Bạn không có quyền truy cập khu vực quản trị.`. Admin/Staff visiting `/admin/login` are redirected to `/admin/dashboard`; API RBAC remains independently enforced. Reporting checks should cover 7-day, 30-day, current-month, custom and zero-data ranges, then cross-check at least one `COMPLETED`/`grandTotal` aggregate through read-only Prisma tooling.

For M7.5A catalog QA, `/admin/catalog` has separate product and classification areas. Classification tabs are Danh mục, Tác giả, and Nhà xuất bản. The default operational filter is Hoạt động; Đã ẩn / QA and Tất cả are explicit audit views. Verify table headers/cells, description wrapping, category sort order, labelled checkbox, separate save/toggle/hide controls, retry state, Staff read-only behavior, and no page-level horizontal overflow. See docs 95-97.

## Smoke Checks

Recommended local smoke checks:

```bash
npm run lint
npm run type-check
npm run format:check
npm run test
npm run build
npm run prisma:validate -w @rosach/api
npm run seed:validate -w @rosach/api
npm run catalog:contract-audit -w @rosach/api
npm audit --audit-level=high
git diff --check
```

Runtime smoke should verify:

- `GET /api/v1/health` returns `ok`;
- public catalog API returns products;
- customer login returns an access token;
- customer cart and orders are readable;
- staff/admin catalog API is protected;
- home, catalog, category list, promotion, product detail, and admin catalog pages return HTTP 200 in the configured runtime;
- browser console has no blocking frontend runtime errors for public routes.

## Known Limitations

- Wishlist/favorites are documented in early scope notes but are not implemented in the current product.
- Admin Operations and Revenue Center is implemented for dashboard, revenue, product statistics, orders, catalog and read-only inventory. User/role management and refund-aware net revenue remain deferred.
- User and role management screens are not implemented; RBAC exists as static backend permission policy.
- Cart is intentionally non-reserving. Inventory is consumed only during successful checkout.
- Product image upload requires Cloudinary configuration. The canonical local demo catalog does not depend on Cloudinary or an external cover service; it uses 96 owned assets under `/product-images/<product-slug>/`.
- Synthetic assets can be replaced role-by-role by preserving the stable filename and updating the typed manifest when metadata changes. See document 89 for the complete replacement and verification workflow.

## Recovery

To reset deterministic demo data and remove proven local QA residue:

```bash
npm run seed:cleanup-local -w @rosach/api -- --confirm-local-cleanup
npm run seed -w @rosach/api
npm run seed:validate -w @rosach/api
```

The cleanup command is guarded by local host/database checks and the explicit confirmation flag. It deactivates matched records before the canonical seed is applied. Never run cleanup commands against production.
