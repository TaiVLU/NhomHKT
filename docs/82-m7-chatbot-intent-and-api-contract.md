# M7.4B Chatbot Intent and API Contract

Status: implemented for Technical Lead review in M7.4B-1.

## Public endpoint

`POST /api/v1/chatbot/search` is public, read-only, and independent of authentication, cookies, sessions, customer data, carts, and orders. It uses the existing global CORS policy unchanged. Typebot's server-side HTTP Request does not depend on browser CORS; any future browser widget still follows the existing web-origin policy.

Request body is a strict JSON object:

```json
{
  "message": "sách dưới 200 nghìn",
  "filters": {
    "category": "van-hoc",
    "author": null,
    "publisher": null,
    "minPrice": 100000,
    "maxPrice": 200000,
    "availableOnly": true
  },
  "source": "TYPEBOT"
}
```

`message` is trimmed, whitespace-normalized, and limited to 500 characters. `filters` is optional, strict, and bounded; `source` is allowlisted to `TYPEBOT`. At least one meaningful message or filter is required. Unknown properties, invalid ranges, arrays/objects in scalar fields, arbitrary URLs, SQL-like commands, bearer values, and internal/customer/cart/order identifier fields are rejected.

## Deterministic behavior

Supported intents are `GREETING`, `PRODUCT_SEARCH`, `PRODUCT_BY_CATEGORY`, `PRODUCT_BY_AUTHOR`, `PRODUCT_BY_PRICE`, `PRODUCT_AVAILABILITY`, `PRODUCT_INFO`, `SHOPPING_GUIDE`, `CHECKOUT_GUIDE`, `ORDER_GUIDE`, `AUTH_GUIDE`, and `FALLBACK`.

Intent precedence is deterministic: `AUTH_GUIDE`, `ORDER_GUIDE`, `CHECKOUT_GUIDE`, `SHOPPING_GUIDE`, `GREETING`, `PRODUCT_BY_AUTHOR`, `PRODUCT_BY_PRICE`, `PRODUCT_BY_CATEGORY`, `PRODUCT_AVAILABILITY`, `PRODUCT_INFO`, `PRODUCT_SEARCH`, then `FALLBACK`. Price precedes category so a price-qualified book query is not misclassified as a taxonomy name.

Price parsing accepts `200k`, `200 K`, `200 nghìn`, `200 ngàn`, `200.000`, `200000`, `dưới 200 nghìn`, `không quá 200k`, and `từ 100 đến 200 nghìn`. ISBNs, years, book quantities, telephone numbers, and order/product codes are not interpreted as prices.

Product intents query only `CatalogService.publicProducts()`, which delegates to the approved public Catalog Read Model. That boundary enforces active, non-deleted products with active sellable variants and applies category, author, publisher, price, and public availability filters. The chatbot requests page 1 with a maximum page size of 3. Static guide and fallback intents do not query catalog or private data.

## Flattened Typebot v1 response

Successful HTTP responses use the normal API success envelope. `data` is flattened-only and contains:

- `intent`, `message`, and authoritative `resultCount`;
- `product1Title`, `product1Author`, `product1Price`, `product1Availability`, `product1Image`, `product1Url`;
- the same fields for slots 2 and 3;
- `suggestion1` and `suggestion2`.

Every missing product slot is represented by `null`; no product array is returned. Canonical product URLs are generated by the backend from the approved web origin and `/sach/{slug}`. Availability is public-safe wording, not an exact stock count. Database IDs, variant IDs, tokens, customer/cart/order/account/admin data, raw records, and internal errors are excluded.

## Public errors

Errors use the stable envelope `{ success: false, error: { code, message }, requestId }`. Implemented mappings are `CHATBOT_INVALID_INPUT`, `CHATBOT_MESSAGE_TOO_LONG`, `CHATBOT_RATE_LIMITED`, `CHATBOT_SEARCH_TIMEOUT`, and `CHATBOT_UPSTREAM_UNAVAILABLE`. `CHATBOT_NO_RESULTS` is reserved for a future contract revision; v1 represents a valid empty search as HTTP 200 with `resultCount: 0` and all product slots `null`.

The dedicated endpoint limiter is 30 requests per minute per client key. It is mounted only on `/api/v1/chatbot/search` and does not alter public catalog limits.
